# 特别装备（策略设置 + 编组页自动穿戴）

「特别装备」是策略设置里的一个开关：打开后，自动执行会在队伍编组页按固定步骤把特别装备穿到当前队伍上，
并在穿戴流程结束（已穿戴 / 未变更 / 放弃）之后才放行「开始战斗」。

本文件只描述当前实现的行为与判据，不记录改动过程。

---

## 设置项

- 设置项名称固定为「特别装备」。
- 两个互斥选项：
  - 「关闭」：默认值。新装、恢复默认、以及旧配置缺该字段时都是「关闭」；自动执行对该次编组页产生 0 次额外点击。
  - 「自动穿戴」：选中之后才显示三个可多选的关卡类型。
- 三个关卡类型：普通、EX、BOSS，分别对应既有枚举 `LabyrinthCombatKind.NORMAL / EX / BOSS`，没有第二套映射。
  三者可任意组合（单勾、双勾、三勾都合法）。
- 空集合是校验错误：「自动穿戴」但一个关卡类型都没勾选时，`LabyrinthStrategySettings.validationError()`
  返回中文错误 `已开启特别装备自动穿戴，请至少勾选一个关卡类型（普通/EX/BOSS）`，设置页保存按钮因此不可用。
  **空集合在执行侧一律解释为「不执行」**，绝不等于「全部关卡」。
- 设置页显示条件与实际执行读同一份字段、同一个判据 `LabyrinthStrategySettings.autoEquipsSpecialEquipment(kind)`。
- 编解码向后兼容：旧 JSON（无该字段）解码成功且等价于默认「关闭」；新 JSON 往返一致。

## 触发前提

- 只在队伍编组页（`LabyrinthEntryPageState.BATTLE_TEAM_SELECTION`）执行。
- 只有本次战斗的 `combatContext.kind` 落在勾选集合内才执行；不在集合内时该流程完全不介入——不点击、不新增等待、
  不新增中间态，既有编组与开战路径逐字不变。
- 关卡类型来源：`LabyrinthNodeTypes.NORMAL_BATTLE -> LabyrinthCombatContext(LabyrinthCombatKind.NORMAL)`，
  EX / BOSS 同理来自 `EX_BATTLE` / `BOSS`。`combatContext` 为空＝不知道类型 ⇒ 不执行。
- 「是否执行」只读启动时抓取的设置快照：运行中保存新配置不改变本轮，只影响下一次启动。

## 执行流程（用户 0–3.2 步）

| 步 | 行为 | 判据 / 备注 |
| --- | --- | --- |
| 0 | 在编组页等待**推荐阵容已全部就位** | 判据是编组计划的 `teamReady`。未就绪时本流程不武装、不点击，把帧交还既有编组路径去选角色。刻意不要求「5 人齐全」：保持当前队伍的场景在 `teamReady` 之后照常进入 |
| 1 | 点击编组页白色圆形「特别装备」入口 | 位置不变量：与白色「取消」同处编组页最底行的白底按钮带，且在「取消」左侧（中心 x 更小，中心 y 差值不超过该行按钮高度的一半）。点击目标由识别给出的矩形中心推导，不写死坐标 |
| 2 | 点击弹窗1「特别装备设定」正文中部的白色「自动装备」 | 弹窗1 的身份由四个锚点同时成立确立：弹窗左边缘角部小图 + **标题文字**「特别装备设定」+ 正文中部「自动装备」+ 蓝钮两态模板之一。标题文字是必需项：面板外观与「系列效果一览」面板共用（见「与系列详情面板的关系」），只有标题能证明这是这两个弹窗 |
| 3 | 点击弹窗2「自动特别装备设定」的蓝色「确认」 | 回到弹窗1 后必须**重新判定**「装备确定」的可点击性，不复用点「确认」之前的结论 |
| 3.1 | 「装备确定」不可点击（含证据不足）⇒ **不点「装备确定」**，点弹窗1 左下白色「取消」回编组页继续 | 游戏提示「特别装备未变更。」是预期结果，不是运行失败；该分支不得报错、不得阻塞开战 |
| 3.2 | 「装备确定」可点击 ⇒ 点蓝色「装备确定」回编组页继续 | 点过之后只等结果：不回退、不重试、不额外点击 |

其他约束：

- 弹窗2 里的勾选框「选择其他角色装备中的特别装备」**不做任何点击或修改**；勾选框的默认状态未知，
  未勾选时要走 3.1 也是正确行为。
- 弹窗1 正文的角色列、弹窗2 的「优先属性值/稀有度」控件都不点击。
- 弹窗2 自己的「取消」不在动作集内（只有弹窗1 的左下白色「取消」会被点，且只出现在 3.1 分支与超限逃生）。

## 「装备确定」两态判定（像素证据）

- 蓝钮在不可点击时只是被压暗，形状与文字完全不变，模板相关度仍然很高、不足以判态。唯一的差别是蓝色填充本身的亮度
  （与商铺买按钮同一手法，见 `LabyrinthShopRecognition.buyButtonEnabledEvidence`），所以判据必须是像素亮度。
- 取蓝钮内芯 `[1487,933..1763,981)` 的平均亮度（0..255）与平均 B−R：
  - 不可点击：lum=93.9 / B−R=89.8；
  - 可点击：lum=152.7 / B−R=112.9；
  - 两类各 3 帧、逐帧一致。阈值取 120（两类间距 58.8，两侧余量 ≥24）；辅助信号 B−R 阈值 101，只做交叉校验。
- 实现用 Rec.709 浮点系数、每 3 px 采样复测同一 ROI：不可点击 95.5 / B−R 89.4，可点击 155.2 / B−R 112.3；
  与上面那组整系数、逐像素的值差 1.6–2.5，来源是系数与采样步长。两组值同在阈值 120 的同一侧，结论一致，
  实现不对齐数字、也不改判据。阈值 120 距两类实测值 ≥24。
- 判定要求**连续两帧同类证据**才给出可点击 / 不可点击；证据不足或证据类别变化时返回 `null`，
  这一帧既**不点**「装备确定」也**不点**「取消」，只等下一帧：
  - 单帧判态会判错：「弹窗2 刚关、弹窗1 正在显现」的过渡帧上，内芯两个信号都可能落在不可点击一侧
    （该帧实测 lum=112.4 / B−R=81.8，而真正可用时是 lum=162.5 / B−R=110.4），于是会误点「取消」，
    而下一帧就已经是可用状态。过渡帧与不可用帧在 B−R 上只差 2.1（81.8 对 88.5），**调阈值解决不了**。
  - 连续两帧「两信号矛盾」按不可点击处理（保守分支）。
  - 弹窗2 打开或无弹窗时证据清零：回到弹窗1 之后必须重新判定。

## 会话执行与闸门

- **一轮的定义**：从首次观测到 `BATTLE_TEAM_SELECTION` 开始，到观测到一个稳定的、非编组页的页面状态为止。
  弹窗1 / 弹窗2 与 `UNKNOWN` 都不算离开编组页；单帧落在别的页面也不算离开（连续两帧才算），
  避免弹窗关合动画、Boss 切队、结算过渡中的误分类把本轮标记清掉。真正离开编组页后标记清零，下次再进入是新的一轮。
- **Boss 多队模式按队伍页签各跑一轮**：多队模式下编组页的页签就是队伍身份，`bossTeamIndex` 一变，上一轮
  （哪怕已经结束）就不属于当前队伍，当前页签重新武装并走完自己的完整一轮（入口 → 自动装备 →
  弹窗2 确认 → 装备确定/取消），上一队的结束标记不会替下一队挡住穿戴。只在上一轮**已经结束**（`DONE`）时
  按页签重开：本轮还在走的时候不会被一帧误分类的页签打断而重新武装；在走的轮次本来也有 8s/3 次上限兜底。
- **空队不跑**：多队模式下某个页签「一位可用成员都没有」（整队没有识别出任何 `characterId`）时不武装、
  零点击，并把这一帧交还既有编组路径——留空页签的推进由它负责（「其余留空，开始挑战」）。
- **单队模式与普通/EX 行为不变**：Boss 单队整段只跑一轮，页签不参与轮次身份；普通与 EX 各自只跑一轮。
- **开战闸门**：本轮没有结束（尚未穿戴 / 未变更 / 放弃）时，不得派发
  `LabyrinthBattleTeamExecutionKind.START_BATTLE`。三条既有开战路径（Boss 部分多队、Boss 单队、普通/EX）
  共用同一个早返回点，因此闸门对三者一致；本轮结束后立即放行。
- **每步上限**：每一步的派发次数上限 `MAX_SPECIAL_EQUIPMENT_STEP_ATTEMPTS = 3`，等待上限
  `SPECIAL_EQUIPMENT_STEP_TIMEOUT_MILLIS = 8000`。超限或超时后：
  - 若弹窗1 还开着且「取消」矩形可信 ⇒ 点左下白色「取消」退回编组页；
  - 否则只给出可诊断消息，并停止自动执行、保留诊断状态（不会安静地停在编组页）。
  - 两种情况都结束本轮并放行开战：宁可这一次没穿上，也不能卡死在编组页。
- 编组页的等待消息覆盖流程自己的状态（等待入口 / 等待弹窗1 / 等待弹窗2 / 证据未稳定等），
  不会落到兜底文案「暂不自动处理，等待画面推进」。
- 流程结束后若弹窗仍开着且没有可派发的逃生点击，会停机并保留诊断原文，不会用「本轮已结束」覆盖它。
- 超限逃生点击派发后只点一次（不再重复点「取消」），并给它一个等弹窗关闭的窗口
  （`SPECIAL_EQUIPMENT_ESCAPE_TIMEOUT_MILLIS = 8000`）；窗口内不重复点击、不停机，超期仍未关才停机。
  逃生点击被动作间隔或单动作锁挡下时不会丢：它记成待办，窗口内间隔到期后补发一次；窗口内始终派发不出去
  （例如单动作锁一直被占）就放弃这次点击，由「本轮已结束但弹窗仍开着」的分支停机并保留诊断。
- **动作节流是会话共享的**：本流程与编组/开战路径共用同一个动作时间戳 `lastSessionActionAt`，任意两次点击
  之间强制 `BATTLE_TEAM_ACTION_INTERVAL_MILLIS = 1200`。弹窗「取消」之后，编组/开战路径即便自己上一次
  动作已经过去很久，也必须再等满 1.2 秒才允许派发「战斗开始」——两条流程各持一个时间戳时，0.76 秒的
  点击会在弹窗关闭动画里被游戏吞掉。点击被拒绝为「不在前台」时共享时间戳清零，回到前台可立即重试。
- **「决定要点击」不等于「点击已经派发」**：会话动作间隔（1200ms）与单动作锁都可能把点击挡在派发之前。
  `specialEquipmentFlowStage` 只在**这一帧没有待派发的点击**、或**待派发的点击确实派发成功**之后才推进；
  被挡下的那一帧保持原 stage、步进次数与步进起点不变，间隔到期后同一条决策会重新算出来补发**一次**。
  入口、「自动装备」、弹窗2「确认」、「装备确定」都走这条规则，所以不存在「已经进入下一个状态却从未点击」
  的等待——那种等待的下一帧不会再生成原来的动作，表现为永久停在「等点击结果」。
  - 补发不引入新的等待：次数只在真的派发时增加，超时按原来的步进起点计时，`MAX_SPECIAL_EQUIPMENT_STEP_ATTEMPTS = 3`
    与 `SPECIAL_EQUIPMENT_STEP_TIMEOUT_MILLIS = 8000` 照常收尾；被拦期间 stage 不动，所以 8 秒上限一定能到点。
  - 唯一的例外是**结束型**的带点击决策（超限逃生点「取消」）：结束标记必须先落下（否则下一帧的「本轮已结束」
    决策不再带这次点击），点击本身记成待办 `specialEquipmentPendingEscape`，在逃生窗口内间隔到期后补发一次。
- **会话/账号边界重置**：本轮状态（stage、步进次数与起点、两态证据计数、Boss 页签身份等）与「上一场普通战斗的
  编组记忆」都属于**本次运行**。`start()` 与 `stop()` 共用 `resetNodeExecutionState()`，那里会
  `resetSpecialEquipmentRound()` 并清空 `lastNormalBattleTeamSignature`，所以复用同一个会话对象跑下一个账号时
  新会话是 `[INACTIVE, null]`：不会带着上一局的 `DONE` 直接跳过穿戴，也不会把上一场的编组记忆当成这一场的
  比较对象。普通战斗之间不经过这个重置点，「编组未变则跳过」照常生效。
- **弹窗关闭后的第一帧让给关闭动画**：本轮看到过弹窗、弹窗已关闭并结束本轮时，会话把交还编组/开战路径的
  那一帧标成关闭 settle，`handleBattleTeamSelectionExecution` 在开战闸门之后、产出任何编组执行步之前
  消费它并直接返回：关闭动画期间不会点「战斗开始」，下一帧照旧放行。

## 普通关卡：编组与上一场完全相同则跳过

- **记忆**：普通关卡在派发 `START_BATTLE` 的那一刻记下本场的队伍签名
  （`labyrinthBattleTeamSignature(step.confirmedTeamIds)`：canonical 后去重、排序、逗号连接）。
  这条记忆跨战斗保留——不在单场重置里，也不在 `resetBattleTeamExecutionTracking` 里；EX 与 Boss 不写它。
  它只跨**同一次运行**内的战斗：`start()` / `stop()` 的会话/账号边界重置会把它清空（见上）。
  这一步派发后画面没有推进（动作没被游戏收下）时，记忆还原成**最近一次派发之前**捕获的值
  （`PendingBattleTeamAction.previousNormalTeamSignature`，在写入本场签名之前捕获）。重试链上的每一次
  派发都按同一规则重新捕获并写回本场编组，所以它不等同于「最近一场真正开起来的战斗」的编组。
- **跳过**：本场普通关卡在武装点若当前队伍与记忆完全相同，就不武装、不点入口、不派发任何点击，
  把这一帧交还既有编组/开战路径（编组与开战照常推进），并给出一条可诊断消息
  「特别装备：本场编组与上一场普通战斗完全相同，跳过本次穿戴」。
- **「完全相同」的四个条件**：
  1. 记忆签名非空（首场没有可比对象）；
  2. 当前队伍非空，且成员数量与记忆相同；
  3. 逐槽都识别出了角色——任一槽 `characterId` 为空就无法证明是同一支队伍，宁可再穿一次；
  4. `characterId` 集合相同（经 `labyrinthBattleTeamSignature` 规范化后逐字相同）。
  任一条件不成立都不跳过，照常走完整流程。
- **适用范围**：只在「自动穿戴」勾选了普通、且本次战斗类型是普通时考虑跳过。EX 与 Boss **永不跳过**：
  即使与记忆里的编组完全相同也必须跑流程。

## 安全边界

- **不会点错按钮**：不可点击或证据不足时，「装备确定」在任何路径上都不会被点击。判定只有一处；
  即便决策层出错，动作矩形解析还会再检查一次「必须明确可点击」，否则不产生点击。
- 3.1 分支与超限逃生都只指向「取消」矩形；超时路径即便此刻按钮可点击也只点「取消」。
- **入口不可信时零点击**：入口锚点分数低于 0.70、或矩形映射失败时，观测返回 `entryButtonRect = null`
  与原因码 `special-equipment-entry-button-not-found`，本流程不点击任何候选位置，跳过本轮穿戴、
  给出可诊断消息，并照常允许开始战斗。
- **两处窄排除**：会话失效判定与「单按钮确认弹窗」判定在特别装备弹窗帧（观测给出弹窗 stage）上都不认领该帧，
  避免自动化去点「返回标题」或把共享的「确认」模板派发到弹窗2 的按钮位置上。`stage` 为 null 时
  （真实的过期弹窗、事件后的确认弹窗）这两个判定的行为不变。

## 已知边界

- **两帧稳定是启发式**：它能挡住「弹窗2 刚关、弹窗1 正在显现」这类过渡帧（实测该帧的两个信号都落在不可用一侧），
  但如果过渡帧连续两帧给出同一类证据（不可用或矛盾），仍然会按 3.1 走「取消」。此时结果与 3.1 相同
  （「特别装备未变更。」），不会点错按钮，但也不会替用户穿上——要更早地判出可用，需要更强的跨帧证据来源。
- **入口几何以基准图为准**：截图那批图的编组页底行按钮位于 y≈922..996，而基准图入口圆环的 y 范围约 864..946，
  两者不是同一行几何。遇到与基准图底行几何不一致的实机帧，会走「找不到可信入口」路径（零点击、跳过本轮、
  照常开战）。
- **判据只在 1920x1080 参考系标定**：只登记 `standard(...)`，不加 `wide(...)`（wide 参考系为 2780x1264，
  本项目没有该类真机基准）。帧尺寸低于 1280x720 时识别层直接返回 null（不做几何推断）。
  1600x720 等未标定尺寸下，弹窗可能识别不出（保守：没有 stage ⇒ 上层不动作）。
- 未验证：无实机回放、无第二分辨率档。入口 ROI 在实机 1920x1080 编组页帧上命中正确
  （圆形按钮位置与标定一致，还带点击反馈圈）。

## 与系列详情面板的关系

「系列效果一览」面板（遗物系列详情，只读、由人工打开）与两个弹窗共用同一套外观：白色面板、
蓝色标题带、白色页脚，四个 8x8 角点探针在该面板与弹窗1 上都是纯白。所以**面板外观不能用来判身份**，
只有内容类特征能分开：

- 身份互斥：系列详情解析器只认面板自己的判据（角点白 + 标题 OCR 读到「系列效果一览」）；
  只要特别装备识别器给出了 `stage`（弹窗1 的四个锚点或弹窗2 的两个锚点成立），该帧就留给特别装备流程，
  解析器不 `hold`、不 OCR，会话里的系列详情分支也不接管该帧。反过来，弹窗1 的必需锚点里有标题文字，
  面板的「系列效果一览」不能让它成立。
- 判据数值：同一 ROI 上弹窗1 右下蓝钮 `(1428,917,396,81)` 的 B−R 为 +100.5（不可点击态 +100.5、
  可点击态 +131），真面板同区为 +7.4 —— 面板上没有这个蓝钮；弹窗1 标题文字的模板分数在弹窗1 各帧
  ≥0.80，在面板帧 < 0.70。
- 该面板的真机反例是 `android/app/src/test/resources/labyrinth/series-effect-panel-20261012.jpg`
  （用户设备 1920x1080 截图）。
