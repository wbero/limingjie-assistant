# EX 配队策略核对（2026-10-05）

依据仓库攻略 [README-ex-mechanics.md](../../role-team-review/README-ex-mechanics.md)，逐项核对当前 14 种 EX。代码基线为上游 `098686e`，本次只修正幽灵领主；其余条目记录实际实现和差距。

## 幽灵领主：已修正

原实现只有单目标输出模型和治疗加分，“1坦 + 4中后排”仅写在说明里。高分近战、同一物理/魔法体系优先搜索，以及失败两次后的补奶，都可能使队友集中到前排。

现在按以下顺序选队：

1. 根据已确认的魔法伤害评估合格一号位；调用者明确传入的敌人伤害类型仍优先。
2. 优先减少靠近一号位的队友数量：起始站位距离不超过 300、站位未知、额外掩护者均视为未满足攻略。这个顺序优先于玩家评分和单一伤害体系；同等站位条件下继续使用原评分。
3. 候选池裁剪时保留远离前排的角色，避免低分中后排在搜索前就被淘汰。
4. “有效效果”核心与最优隔离站位冲突时，优先隔离站位。首次编组、未重复失败的重试，以及失败两次后的补奶都遵守这一顺序。
5. 角色不足时仍组满五人，尽量减少受波及者，并显示未满足的条件；无合格前排时继续保留现有兜底提示。

这使用角色数据库的 `position`（来自 `unit.search_area_width`）估计开局相对站位。技能移动、击退和嘲讽后的实际战斗位置不在该估计内，不能将起始距离理解为整场 UB 都不会波及。治疗仍为偏好，没有强制锁定指定角色；抽敌方 TP 也没有新增强制要求。

实现见 [LabyrinthEncounterFormation.kt](../app/src/main/java/com/landosol/toolbox/labyrinth/LabyrinthEncounterFormation.kt)、[LabyrinthRoleDecisionPolicy.kt](../app/src/main/java/com/landosol/toolbox/labyrinth/LabyrinthRoleDecisionPolicy.kt) 和 [LabyrinthBattleTeamRecommendation.kt](../app/src/main/java/com/landosol/toolbox/labyrinth/LabyrinthBattleTeamRecommendation.kt)。

## 共用流程及发现

当前生产流程是：识别 EX 身份 → 编组前扫描游戏“有效效果” → 从有效角色及攻略能力中选核心 → 搜索五人阵容 → 评分 → 排除失败阵容后重试；EX 失败两次后另尝试补奶。攻略文件顶部“一队先打，失败后才扫描”的流程已落后于当前实现，本文以生产入口为准。

其他 EX 存在两个共用缺口，本次未改变其行为：

- `labyrinthEncounterGuideCore` 先按玩家分加入所有有效角色，再补能力要求，最后只取前 3 个核心。如果有 3 个高分有效角色不具备 DOT/控制等能力，后加入的能力角色可能被截掉。不能据 `requirements.hard = true` 就认定是不可绕过的硬约束。
- 核心保留主要用于首次编组。普通失败重试重新按评分选未失败队伍，攻略要求仍是加分；第二次失败的补奶保护合格前排及有效角色，没有保护所有攻略能力核心，可能丢失 DOT/控制。幽灵领主本次单独增加了站位优先检查，其他 EX 仍沿用原行为。

建议后续优先处理蜂后的 DOT、美空的后排覆盖、熔岩龙集中站位，以及能力核心被有效角色挤占/重试移除的问题；岛鲸和吞拿鱼还需要把“前 N 位耐久”转为可执行条件。战斗时机与机器人实际命中需要更多运行期信息，单靠能力标签无法保证。
